# Waypoint

An Android app with an LLM Coach. The v1 spec is `docs/spec/v1.md`; the domain terms are in `GLOSSARY.md`. Use the glossary's terms in code, tests and UI copy (Aspiration, not goal; Check-in, not log).

## Layout

- `server/`: the ASP.NET Core API (.NET 10, EF Core with Pomelo on MySQL 8). Solution `server/Waypoint.slnx`; tests in projects under `server/` that the solution includes.
- `app/`: the Expo app (React Native, TypeScript strict, Expo Router). npm scripts `typecheck` (`tsc --noEmit`) and `test` (Jest).
- `docker-compose.yml` at the root: the API and MySQL.
- `prototypes/`: throwaway Coach prompts, sample hand-offs and eval cases from the planning phase. Reference material for the real prompts, never imported by app or server code.
- `docs/spec/`: the spec. Tickets live in ClickUp and point at its sections.

## Commands

- Server: `dotnet build server/Waypoint.slnx`, `dotnet test server/Waypoint.slnx`. API tests use Testcontainers, so they need Docker.
- App: `npm ci --prefix app`, `npm run --prefix app typecheck`, `npm test --prefix app`.
- Android builds are CNG: `android/` is generated by `npx expo prebuild` and never committed.

## Conventions

- **Test at the seams** in the spec's Testing Decisions: the server's HTTP API in-process against MySQL in Testcontainers, with a fake clock, fake model client, fake Google verifier and fake FCM sender; the phone's storage interface, outbox and Check-in task with Jest. Assert observable behaviour, not private methods.
- **Time is injected** on the server (no `DateTime.UtcNow` in domain code), so jobs and weekly refreshes are tested by advancing a fake clock.
- **Every user-owned row has `UserId`**, enforced by the EF Core global query filter. Never bypass it outside sign-in.
- **Free text never goes into logs, error traces or job payloads.** Jobs refer to rows by ID.
- **The model key stays on the server.** Every Coach call goes through the one Coach model client; the model per kind of call is configuration.
- **Pace, Projection, tolerance and the Plan's hard rules are server code**, never model output. The model phrases results; the server decides them.
- **The Coach is late, never faked**: no canned lines in the Coach's voice when a model call fails.
- **App UI**: every string through i18next; layouts use start/end, never left/right; styles from the Unistyles theme tokens, not literals.
- **Secrets** (Google client IDs, Firebase service account, Anthropic key, connection strings) come from environment variables or user secrets, never committed.
